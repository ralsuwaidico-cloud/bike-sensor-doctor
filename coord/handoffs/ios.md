## What changed

All Link 1.3 behaviour is capability-gated twice: `Link13Session` (INFO cap 0x0800 → APP_HELLO → only the features in
HELLO_ACK's `enabled_caps`) and `DeviceLink.sendLink13`, which refuses any Link 1.3 byte to a board without cap 0x0800.
With firmware 0.7.3 (and every board that does not advertise the cap) the app behaves exactly like the release candidate:
no new bytes, DIAG_ACK without tag 03, the Storage page says "needs a BikeComputer firmware with Link 1.3".

## Safety rules implemented (and tested)
- RIDEQ_ACK only after: stored file size + CRC-32 verified, ride saved in Cyclift's history (store written without error),
  and the board's `summary_crc32` equals the CRC Cyclift computed over that ride's SYNC_RIDE fields (Q-iOS-1).
  `delete_samples = 1` then. Demo, recording and conflicting rides are never ACKed; a stored ride is never pulled twice.
- Safe cleanup sends only bits 0–2, only after a confirmation dialog listing what always stays; disabled for damaged
  filesystems ("never repaired over Bluetooth"), while the board records, and for boards without Link 1.3 storage.
- COACH_STATE names the HR source the phone coach used; "Apple Watch HR live" (flag bit2, src 4) only while the watch HR
  is live on the phone. Phone-only rides are not mirrored (Q-iOS-13).
